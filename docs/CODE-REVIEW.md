# VilHil Studio 代码评审标准

## 1. 评审目标

优先发现行为风险、状态分叉和回归风险，不做纯风格争论。

## 2. 风险优先级

1. P0: 会导致功能不可用、数据错误、权限越界。
2. P1: 高概率业务回归或关键路径体验劣化。
3. P2: 可维护性/一致性问题，短期可运行。
4. P3: 建议性优化。

## 3. 必查清单

1. 是否先有工具函数，再有 UI 包装。
2. 是否遵守 `useScene` 与 `useDeviceState` 真值分层。
3. 是否保持“单次交互单语义”。
4. 是否保证楼层作用域一致。
5. 是否有执行态可观测反馈（idle/running/active）。
6. 是否复用 UI 标准（按钮、颜色、圆角、尺寸）。
7. 是否补充或更新 BDD 场景。

## 4. 典型反模式

1. 组件内直接写跨模块业务编排。
2. 直接在 UI 层批量改设备真值，绕过工具层。
3. 聚焦和显隐绑定在一个点击动作上。
4. 画布与面板数据来自不同楼层作用域。

## 5. PR 描述模板

```md
## 变更目的
- 解决了什么业务问题

## 实现方式
- 新增/修改了哪些工具函数
- UI 如何调用

## 风险与兼容
- 潜在影响范围
- 向后兼容说明

## 验证
- 类型检查/构建结果
- BDD 验收点

## 文档同步
- 更新了哪些 docs 文件
```

## 6. 合并门禁

1. P0/P1 未关闭不得合并。
2. 涉及数据契约或状态流变更，文档未同步不得合并。
3. 无验证记录不得合并。
