# 本地开发服务生命周期

> 2026-09-21：修复 Next.js 16.2.1 在输出断管后反复记录 EPIPE 的启动边界问题。
> 本文只涉及开发服务，不改变生产启动、数据库、业务数据或渲染表现。

## 使用方式

- `bun dev`：前台运行，适合持续打开的终端；Ctrl+C 或启动方退出时停止子进程。
- `bun run dev:start`：后台运行，适合 Codex 任务结束后继续使用；等待健康检查成功后才报告已启动。
- `bun run dev:status`：查看本项目管理的 PID、日志路径和健康检查结果。
- `bun run dev:stop`：只停止具有匹配进程身份记录的本项目开发服务。
- `bun run kill`：兼容旧入口，改为调用安全停止，不再按端口批量 SIGKILL。

后台日志在 `docs/tmp/dev-service/dev.log`，每份最多约 5 MiB，保留两个历史文件。
断管/所有者退出记录在同目录的 `faults.log`。这些本机运行文件已被 Git 忽略。

## 运行边界

启动器负责消费子进程输出并写入轮转文件；后台模式不继承任务的 stdout/stderr 管道。
Node 预加载保护只处理 stdout/stderr 的 EPIPE：同步留下简短诊断并退出 74，避免交给 Next 的异常日志循环。其他错误仍保持原有异常行为。
受管理的 Node 子进程也会检查服务所有者是否仍存在，防止所有者异常消失后静默残留。

停止依赖 PID 与进程启动身份匹配，发送 SIGTERM；本项目进程组超过宽限期仍不退出时才升级处理。
发现 3002 被其他进程占用时启动失败，不杀占用进程。重复启动复用已管理的服务，不产生第二套服务。
数据库有独立生命周期，停止开发服务不会停止或修改 PostgreSQL。

## 验收场景

```gherkin
Given 开发服务使用当前安装的 Next.js 异常处理器
When stdout 或 stderr 的读取端关闭后再次写入
Then 子进程在限定时间内退出，故障文件记录 EPIPE
And 普通业务异常仍可记录，不被笼统吞掉

Given 后台开发服务已通过健康检查
When 启动命令退出或重复启动
Then 服务仍正常响应，重复启动返回同一 PID
When 执行停止命令
Then 受管理的进程组退出，3002 释放，其他进程不被终止
```

性能审查中另外三项（隐藏窗帘、PCFSoftShadowMap、渐变传入 THREE.Color）保持为后续独立修复项。
当前脚本针对本项目 macOS/POSIX 开发环境；尚未支持 Windows 进程组管理。
