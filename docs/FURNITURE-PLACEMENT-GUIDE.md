# 家具布置指南（AI 学习手册）

> 本文件记录"在户型里合理摆放家具"的规则和经验，由用户人工示范教学，AI 观察并沉淀成规则。
> 后续 AI 批量布置家具时必须参考本指南。
> 维护者：所有后续接手的 AI。发现用户新的偏好和纠正时，**立即回写**到对应章节。

## 1. 为什么要有这份文档

AI 拿到的数据是：房间 polygon（zone）+ centroid，以及家具 catalog（尺寸 + 分类）。
**AI 缺失的是**：
- 房间的**朝向感**（哪面是主墙、门在哪、窗在哪）
- 家具之间的**关系组**（床头柜必须贴床两侧、茶几面对沙发、电视柜面对沙发）
- 家具的**旋转**（床头靠墙而非对着门、沙发面对电视而非窗）
- **走道和功能流线**（不能挡门、不能挡床侧通道）

这些都需要人类经验。此文档就是把经验沉淀成可执行的规则。

## 2. 工作协议

### 2.1 怎么教（用户）

1. 启用**自由放置**：`localStorage.setItem('vilhil.freePlacement','1')` 后刷新，编辑器不再吸附/拦截。
2. 用户在 2D 或 3D 编辑器里拖动家具到位。
3. 完成后告诉 AI："摆好了"。

### 2.2 怎么记（AI）

1. 读 localStorage 所有 `type==='item'` 节点 → 每件家具的 `position` / `rotation` / `asset.id` / `asset.dimensions`
2. 用 centroid 做 point-in-polygon → 判断所在 zone
3. 对比 AI 原先"盲摆"，提取差异模式：
   - 位置偏移（距离最近的墙/门/窗）
   - 旋转变化（是否对齐墙的朝向）
   - 新增分组（床+床头柜 × 2 三件套）
4. 把规律更新到 §3/§4 对应章节

### 2.3 记录格式

每条规则遵循：
```
**规则名**：<一句话概括>
- 适用场景：<何时生效>
- 做法：<具体坐标/旋转/组合逻辑>
- 反例：<AI 常犯的错>
- 学习自：<日期 / 观察到的户型>
```

## 3. 按房间类型的布置规则

### 3.1 主卧

**床头必须靠墙**
- 适用场景：双人床 / 单人床
- 做法：床的 position 贴最近的完整墙面（优先北墙或西墙，避开带门的墙）。rotation.y = 让床头朝墙（若墙在 X 方向则 rot=90°、墙在 Z 方向则 rot=0）。
- 反例：AI 常把床放房间 centroid 且 rot=0 → 床头朝空气
- 学习自：2026-04-17 主卧户型 → `double-bed @ (-3.85, -2.2, rot=90°)`，房间 centroid (-3.29, -1.6)，床 X=-3.85 贴西墙 (X≈-4.86)

**床头柜在床两侧**
- 适用场景：双人床
- 做法：床头柜 × 2，在床头方向的**两侧**（沿床宽方向 ± (床宽/2 + 柜宽/2)）。rotation 与床相同。
- 反例：AI 把床头柜放床的左右（沿床长方向） → 其实是床的**前后**
- 学习自：同上 → `bedside-table @ (-4.49, -3.3) 和 (..., ?)`

**衣柜靠最长完整墙**
- 适用场景：主卧
- 做法：沿最长且没开门开窗的墙一字排开。rotation 让 1m 深那边朝外（长边贴墙）。
- 学习自：`closet @ (-4.4, -0.25, rot=90°)`，靠西墙

### 3.2 次卧

**床尺寸降为单人或双人**
- 适用场景：小房间（<10㎡）
- 做法：`single-bed [1.5×0.7×2.5]`，床头贴一面墙，预留一侧通道 ≥0.6m。rot 通常 90°。
- 学习自：南次卧 7.9㎡ → `single-bed @ (-0.6, -1.95, rot=90°)`

### 3.3 客厅

**沙发 — 茶几 — 电视柜 一条直线**
- 适用场景：客厅
- 做法：三件沿同一条 X（或 Z）坐标线等高排开，间距：沙发↔茶几 1.2~1.5m、茶几↔电视柜 1.0~1.3m。rotation 全部一致（例如都 90°），让长边沿同一方向。
- 反例：AI 把茶几放在沙发"下方"（沿 Z 拉开 1.2m）→ 实际应该沿 X 排开，三件都"面向东墙"或"面向西墙"
- 学习自：客厅和阳台 → `sofa @ (1.7, -1.85, rot=90°)` → `coffee-table @ (3.05, -1.85, rot=90°)` → `tv-stand @ (4.35, -1.8, rot=90°)`，Z 固定、X 递增，都 rot=90°

**电视贴电视柜上方墙**
- 做法：TV 位置和电视柜几乎重合（X 略大即贴墙），rotation 与电视柜一致。`television` 不是家具分类而是单独 asset。
- 学习自：`television @ (4.65, -1.85, rot=90°)` 紧贴电视柜后面

**封阳台区 = 室内延伸功能区**
- **文化背景**：中国家庭普遍会把阳台"封起来"（封阳台），原开放式阳台变成室内延伸空间，用作洗衣、晾衣、健身、储物等。
- 适用场景：zone 名字带"阳台"或两个功能合并命名（如"客厅和阳台"），室内有靠外墙的长条形区域。
- 做法：阳台（通常是有窗户那一端、靠外墙）放功能家具：
  - 洗衣机 `washing-machine`（贴外墙近排水处）
  - 动感单车 `exercise-bike` / 跑步机（中间活动区）
  - 晾衣架（暂无 asset）
- 反例：AI 把阳台当"户外"忽略，或只放植物做装饰。
- 学习自：客厅和阳台 zone → `washing-machine @ (1.55, -4.45)` 和 `exercise-bike @ (3, -3.9)`，都在 Z 较小（南端）靠外墙

### 3.4 餐厅

**餐椅在餐桌 3 面（不是 4 面）**
- 适用场景：餐桌靠墙时
- 做法：先判断餐桌哪条长边贴墙（通常靠北墙或东墙），剩余三面各放 1 把餐椅，rotation 面向桌心。
- 反例：AI 默认 4 角各放 1 把
- 学习自：`dining-table @ (2.9, 1.75, rot=90°)` + 3 把餐椅 (2.25,1.3)/(3.6,1.3)/(2.25,2.2)，北侧空

**餐厅角落放装饰植物**
- 做法：大型 `indoor-plant` 放餐厅角落（非门窗处）。
- 学习自：`indoor-plant @ (4.15, 0.35)` 餐厅东南角

### 3.5 书房

**书桌长边贴墙**
- 做法：`desk` rotation 让长边 1.4m 贴墙、深 0.7m 朝室内。
- 学习自：`desk @ (-2.85, 2.55, rot=90°)` 靠西墙

**办公椅面向桌（rotation 相反）**
- 做法：`office-chair.rotation.y = -desk.rotation.y`（或 desk.rotation.y + π），位置在桌的深度方向 ~0.6m 处。
- 学习自：`office-chair @ (-2.25, 2.6, rot=-90°)`，桌 rot=90° → 椅 rot=-90°（背靠桌）

### 3.6 厨房

**L 型台面沿两面墙**
- 做法：`kitchen-counter [2×0.8×1]` × 2，一个贴北墙、一个贴西（或东）墙，rotation 各自让长边贴墙。
- 学习自：`kitchen-counter @ (1.61, 5.2, rot=0°)` 北墙 + `kitchen-counter @ (0.85, 3.9, rot=90°)` 西墙

### 3.7 卫生间

**三件套沿同一面墙一字排**
- 适用场景：小型卫生间（<5㎡）
- 做法：马桶 `toilet` + 淋浴 `shower-square` + 浴室柜 `sink-cabinet` 全部 rotation 一致，沿同一面墙不同 Z 坐标排开。
- 反例：AI 容易三件放三个角，流线差
- 学习自：
  - 公共卫生间：`toilet @ (0.65, 2.2, rot=270°)` + `shower-square @ (-0.11, 3.2, rot=90°)` + `sink-cabinet @ (0.75, 1.35, rot=270°)`（同 X 附近，Z 不同）
  - 主卫：`shower @ (-4.35, 3.63)` + `toilet @ (-4.35, 2.35)` + `sink @ (-4.55, 1.42)`（X 都在 -4.35~-4.55，Z 分散）

### 3.8 玄关

**冰箱放玄关不是"规则"，而是连通空间的功能外溢**
- **户型背景**：当**厨房和玄关之间没有物理墙隔断**（开放式厨房/无门厨房）时，玄关其实是厨房的延伸，它距餐厅也很近。此时厨房的 **L 型台面占满了厨房墙面**，冰箱没地方放，就"溢出"到玄关靠餐厅那一侧的墙。
- 判定依据（AI 要自己推理）：
  1. 相邻 zone "厨房" 和 "玄关" 之间是否有连续墙段？
  2. 如果**没有**：把它们视为一个连通功能区，冰箱按"离餐厅最近 & 不挤台面"放置，结果往往落到玄关那一侧。
  3. 如果**有墙隔断**：冰箱应该在厨房内部。
- 反例：
  - AI 死记"冰箱放玄关"→ 下次遇到有独立厨房门的户型，冰箱还被塞到玄关（错）
  - AI 按 zone.name 机械分配家具 → 忽略了 zone 之间的物理连通性
- 学习自：本户型"厨房-玄关-餐厅"三个 zone 无墙隔断 → `fridge @ (4.65, 2.73, rot=270°)` 放玄关东墙，实际上紧邻餐厅 centroid (2.77, 1.11)，距离约 2.3m

**可放 1 把椅子（换鞋凳）**
- 做法：小型座椅（如 `dining-chair`）在玄关靠墙处，rotation 面向入户门或室内。
- 学习自：`dining-chair @ (3.6, 2.2, rot=270°)` 玄关

### 3.9 过道

暂无固定规则，本户型过道未放家具。

## 4. 跨房间通则

### 4.1 旋转 — 这是 AI 最大的盲点

**家具长边必须沿主墙方向**
- **判定方法**：对房间内的墙按长度排序，取最长墙段的走向。若该墙沿 Z 方向（朝北朝南走），则大多数家具 rotation.y = 90°（让原默认的 X 长边转到 Z）；若最长墙沿 X 方向，则 rotation.y = 0°。
- **此户型绝大多数墙沿 Z 方向** → 本次 27 件家具中约 22 件 rotation = ±90°
- 反例：AI 盲摆全部 rot=0 导致家具"横着的"横躺在"竖着"的房间里
- 学习自：本次布置后统计：rot=0 → 3 件；rot=90° → 18 件；rot=-90°/270° → 6 件

### 4.2 position 贴墙原则

- 家具 position 不是房间 centroid，而是**贴最近的主墙**（家具几何中心离墙≈家具在墙法线方向半深）。
- 自由放置模式下，position 有时**略超 zone polygon**（zone 画得略保守 or 家具凸出到墙内），AI 不要把它当成"出界"。
- point-in-polygon 失败**不是错误**。

### 4.3 家具组合识别

一些家具必须作为"组"处理，单独放毫无意义：

| 组名 | 成员 | 关系 |
|---|---|---|
| 卧室套 | 床 + 床头柜 × 2 + 衣柜 | 床头柜贴床头两侧；衣柜另一面墙 |
| 客厅套 | 沙发 + 茶几 + 电视柜 + 电视 | 一条直线、等高 rot；电视紧贴电视柜 |
| 餐套 | 餐桌 + 餐椅 × 3（桌靠墙）或 × 4（桌居中） | 椅面向桌 |
| 卫浴套 | 马桶 + 淋浴 + 浴室柜 | 沿同一面墙排开 |
| 工作套 | 书桌 + 办公椅 | 椅在桌深方向 0.6m，rotation 相对 |

### 4.4 家具与窗/门的关系

- 床/沙发/衣柜/电视柜 **不能压在门洞上**（门打开会撞）
- 床**尽量不挡窗**（床头可以在窗下墙，但床身不遮窗光）
- 冰箱/洗衣机 **可以靠窗**（不影响通风）
- 暂缺：具体距离阈值待下次观察补充

### 4.5 跨区域家具类别表

| 家具 | 常见房间 | 备注 |
|---|---|---|
| 冰箱 fridge | 厨房 / 玄关（连通时外溢） | 按 §4.6 连通性判定 |
| 洗衣机 washing-machine | 阳台（封阳台）/ 卫生间 | §3.3 中国家庭封阳台常见 |
| 动感单车 exercise-bike | 阳台（封阳台）/ 客厅 | 阳台是主选 |
| 电视 television | 客厅 | 贴电视柜后墙 |
| 厨房台面 kitchen-counter | 厨房 | L 型 × 2 |
| 马桶 / 淋浴 / 浴室柜 | 卫生间 | §3.7 三件套沿同墙排 |

### 4.6 【元规则】zone 名字 ≠ 物理隔断

**这是 AI 最容易犯的"想当然"错误。**

Zone 是用户在 2D 编辑器画的语义分区，**不代表其间有墙**。两个相邻 zone 之间是否隔断，必须**看墙数据**而不是 zone 名字。

**算法要求**：布置家具前必须先算**zone 连通图**：

```ts
function computeZoneConnectivity(zones: ZoneNode[], walls: WallNode[]): Graph<ZoneId> {
  // 对每对相邻 zone（polygon 共享线段或距离 <0.3m），
  // 检查它们的边界上是否有连续墙段（长度 ≥ 共享边界 70%）。
  // 无墙 → 两个 zone 相连，视为同一功能区
  // 有墙 → 独立空间
}
```

**推论**：
- **家具归属不看 zone.name 而看连通功能区**：
  - 独立厨房 → 冰箱在厨房 zone
  - 厨房-餐厅-玄关连通（无墙）→ 冰箱按"最近空墙 + 距餐厅近"原则放，可能落在任一 zone 内部（本户型落玄关）
- **"客厅和阳台"合并 zone** → 用户明确告诉你这两个功能区是连通的，直接视作一个功能区来处理
- **"过道"通常是连通多个 zone 的纽带** → 不放大件家具，可放小盆栽点缀

**文化常量 — 中国家庭特点**（后续遇到新模式往这里加）：
- 封阳台：阳台几乎都被玻璃窗封起来，是室内延伸，放洗衣机/健身/晾衣等功能家具，不要当户外处理
- 开放式厨房：城市户型常见开放厨房，家具规划要把厨房+餐厅+玄关作为连通区整体考虑
- 主卧卫生间常套间（主卫与主卧相邻有门）
- 北方户型多南北通透、南方户型重视采光朝向

## 5. AI 自动摆放算法草案

等规则足够具体后，转译成 `packages/smarthome/src/tools/auto-layout.ts`。当前草案：

```ts
function autoLayoutRoom(zone: ZoneNode, walls: WallNode[]): ItemNode[] {
  // Step 1: 识别房间类型（靠 zone.name 前缀/包含匹配）
  const kind = classifyRoom(zone.name)  // '主卧' | '次卧' | '客厅' | '餐厅' | '书房' | '厨房' | '卫生间' | '玄关' | ...

  // Step 2: 计算房间的"主墙方向"
  //   - 取房间相邻（距离 zone polygon 最近的）所有墙
  //   - 按长度排序，取最长墙
  //   - 墙若沿 Z 方向 → primaryAxis='z'，默认家具 rotation.y = 90°
  //   - 墙若沿 X 方向 → primaryAxis='x'，默认家具 rotation.y = 0°
  const primaryWall = findPrimaryWall(zone, walls)
  const defaultRotY = primaryWall.axis === 'z' ? Math.PI / 2 : 0

  // Step 3: 按房间类型选家具组 + 贴墙定位
  switch (kind) {
    case '主卧':
      return placeBedroomSet(zone, walls, defaultRotY, { bedSize: 'double' })
    case '次卧':
      return placeBedroomSet(zone, walls, defaultRotY, { bedSize: 'single' })
    case '客厅':
      return placeLivingRoomSet(zone, walls, defaultRotY)
    case '餐厅':
      return placeDiningSet(zone, walls, defaultRotY, { tableAgainstWall: true })
    case '书房':
      return placeOfficeSet(zone, walls, defaultRotY)
    case '厨房':
      return placeKitchenSet(zone, walls)  // L 型台面
    case '卫生间':
      return placeBathroomSet(zone, walls, defaultRotY)  // 三件套沿一面墙
    case '玄关':
      return placeEntrySet(zone, walls, defaultRotY)  // 冰箱 + 换鞋凳
    default:
      return []
  }
}
```
