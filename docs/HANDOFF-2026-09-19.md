## 5. 优先处理的问题

### P1：现有场景 Tween 数值动画没有进入全局更新组

`packages/smarthome/src/tools/scene-tools.ts` 使用 `new TWEEN.Tween(fromObj)`，驱动却调用 `TWEEN.update()` / `TWEEN.getAll()`。锁定的 Tween 25 默认不自动加入全局组。

依赖级最小复现结果：创建并启动 0 → 100 的 brightness tween 后，`TWEEN.getAll().length === 0`；执行 `TWEEN.update(100)` 后 brightness 仍为 0。结合调用点可定位数值过渡不执行的原因；完整“回家场景”UI 回归尚未进行。

下一步在 smarthome 工具层显式管理 tween group，覆盖动画完成、中断和重复执行，再验证灯光/窗帘场景。此次保留原有工作区改动，没有顺带修业务逻辑。

### P1：类型检查未通过，生产构建绕过类型错误

`apps/editor/next.config.ts` 已有 `typescript.ignoreBuildErrors: true`。editor 错误涉及节点 ID 类型、R3F JSX/事件、旧 roofHeight 字段、楼梯面板节点联合和导出参数等。app 还有原生 button 的 variant、PDF 类型及场景快照类型问题。

先按根因分组修复并保持每组可验收；不得靠继续扩大 any 或关闭检查宣称通过。生产构建成功不能替代类型检查。

### P1：生产初始化流程与当前 Auth schema 不完整对应

历史 SQL 缺少 admin 插件的 `user.banned / banReason / banExpires`、`session.impersonatedBy`。Drizzle journal 又不包含两个手写 Auth SQL。本次专用本地脚本补齐了开发库，但没有修正或执行生产迁移。

生产发布前需形成独立、审阅过的迁移增量，并核对部署脚本的部分失败/重跑行为；不能把本地数据库已成功当成生产迁移已解决。

### P2：架构与文档仍需逐步收敛

- `DATA-SCHEMA.md` 的概念对象与实际序列化结构存在差异；设备运行态实际是 `state`，设备楼层需沿 `parentId` 确认。
- 原有 `playerGetDevices(levelId)` 按不存在于 DeviceNode schema 的顶层 levelId 过滤；使用前应与已有楼层工具统一。本次未将未调用的门面接入 UI。
- 场景运行状态实际是 scene-tools 模块的 `{sceneId, running, startedAt, expectedEndAt, completedAt}`，不是文档示例中的 useScene 字符串枚举；后续需先对齐契约再改实现。
- `floorplan-panel.tsx` 约 12,276 行；设备、拓扑、渲染模块也有超过项目 800 行规约的文件。应围绕已验收边界逐步迁出，避免在初始化期间大拆。
- 老文档的“8 个 schema 已删除”“registry 仍为空”“middleware 已关闭”“operate 仍只是 readOnly=false”均不能作为当前事实，相关入口文档已校正。
