## 既有问题和边界

详情页持续出现 `SelectiveBloom requires lights to work`、layer out of range 和 React maximum update depth 告警。导航修复前的 `docs/tmp/studio-integrated-2026-10-06/next-dev.log` 已记录同样告警（首处第 245 行），不是本轮入口代码新引入。已装 postprocessing 的 Select/selection 注册依赖与 SelectiveBloom 生命周期是下一步调查点；本轮不改依赖或后处理，不把“能点击完成”说成“整页无错误”。

HDR 外部 CDN 与部分 Iconify 请求在此执行环境失败，页面使用原有 HDR 降级。截图取真实默认无 MSAA 路径，蓝调/玻璃叠加及整体明暗与认可舞台不同，保留给用户确认；没有为了截图替换材质或灯光。Linux SwiftShader 下的帧率不代表用户 GPU，但上述 React 循环也不能只归因软件渲染。

保存边界：编辑器 autosave 后刷新及展示页重新进入均恢复保存快照。既有展示页临时设备操作不自动覆盖项目；本轮没有新增演示持久化，刷新会恢复已保存状态。双层逐层渲染/状态仍由前轮真实组件回归验证；展示页原浮卡仅有整体 position，未扩成双层控制面板。

## 后续顺序：空调，再摄像机

以下只读源码观察不是浏览器验收，不依据旧待办勾选判断功能缺失：

1. **空调已有实现**：`device-effects.tsx` 把 `vent-4way` 接到 `HvacAirflow`、`ac-wall` 接到 `HvacRibbonFlow`，从 useScene 读取 on/mode；已有冷/热配色与关闭强度衰减。`DeviceInfoCard` 已有开关、16–30°C 目标温度、制冷/制热/关闭。旧 BDD P2.5-5 列明冷/热颜色、500ms 过渡、关闭 3s 隐藏；待下一轮实测。建议先核对实际项目设备类型及默认展示入口，再测冷/热/关、安装朝向与隐藏/卸载，复现后仅修必要问题。
2. **摄像机已有实现**：DeviceNode 的 `dome` / `camera-bullet` 走 `LaserScanCone`，读取覆盖角度、距离、方向，离焦强度为 0.25；DeviceInfoCard 有 FOV/距离控制。另有 ItemNode.cameraParams 的旧 `CameraInfoCard`，展示朝向/FOV/距离，两种数据入口需先分清。当前 LaserScanCone 参数改变会重新创建 ConeGeometry，与旧 BDD “只改 uniform、不重建”不一致，不能直接宣称该验收已完成。建议空调完成后再测试实际摄像机模型、覆盖方向、FOV/距离及聚焦，避免混改两条路径。

暖通和安防在 proposal-demo 中仍受原有非灯光入口/目标范围限制；本轮按授权只补窗帘，未顺手改变这两个子系统。下一轮先做入口可用性诊断并报告最小范围，再由父任务协调体验目标。没有接入 Home Assistant、真实摄像流、私人监控或新增权限。
