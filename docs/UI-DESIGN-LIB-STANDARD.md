# VilHil Studio UI 设计库与标准（v1.0）

> 目标：把“编辑模式 + 展示模式”统一到同一套设计语言、交互语义与组件资产中。  
> 适用范围：`apps/editor`、`packages/editor`、`packages/viewer`、`packages/smarthome` 的所有 UI 改动。

配套细则：

1. 单一标准源：`docs/UI-STANDARD.md`
2. 组件库细则：`docs/UI-COMPONENT-LIBRARY.md`
3. 逻辑架构细则：`docs/UI-LOGIC-STANDARD.md`

## 非技术版摘要（给负责人）

这份标准可以理解成 4 句话：

1. 所有 UI 都服务 3D 场景理解，不做花哨但无信息价值的东西。
2. 一次交互只做一件事（比如“聚焦”和“显隐”必须分开）。
3. 编辑模式和展示模式是同一种视觉语言，但权限不同。
4. 团队新增页面必须复用现有组件和 Token，避免越做越乱。

---

## 1. 设计原则

1. 空间优先：所有 UI 必须服务 3D 空间理解，不可喧宾夺主。
2. 语义单一：一次交互只做一件事（选择、切换、执行不可混合）。
3. 渐进披露：常用动作直达，高级配置折叠。
4. 模式一致：编辑模式与展示模式共享视觉语言，不共享操作权限。
5. 反馈即时：任何状态改变必须在 300ms 内有视觉响应。

---

## 2. 信息架构标准

### 2.1 主导航层级

- `L0` 应用层：项目、设置、主题、单位。
- `L1` 工作面板层：建筑、设备、场景、交付（占位可灰化）。
- `L2` 画布操控层：构建工具、视图切换、相机动作。
- `L3` 节点属性层：对象参数、联动配置、流程编辑。

### 2.2 模式边界

- 编辑模式：允许创建、编辑、删除节点。
- 展示模式：只允许设备操控与场景执行，不允许结构编辑。

## 3. 视觉 Token 标准

### 3.1 品牌与系统色

- 品牌主色：`#2D7FF9`
- 子系统色：
  - architecture `#94a3b8`
  - lighting `#d4a853`
  - panel `#c8b8a0`
  - sensor `#4ade80`
  - curtain `#3dd9b6`
  - hvac `#9b7bea`
  - av `#5ba0f5`
  - security `#f59e0b`
  - network `#60a5fa`

### 3.2 圆角、阴影、层级

- 面板容器圆角：`rounded-2xl`
- 卡片圆角：`rounded-xl`
- 小控件圆角：`rounded-md`
- 浮层阴影：`shadow-lg` ~ `shadow-2xl`
- 玻璃化底：`bg-background/95 + backdrop-blur-xl`

### 3.3 字体与层级

- 标题：`text-sm font-semibold`
- 正文：`text-sm font-medium`
- 辅助：`text-xs text-muted-foreground`
- 微标签：`text-[10px]`

### 3.4 间距节奏

- 主节奏：`2 / 3 / 4 / 6 / 8 / 12 / 16 / 24`
- 面板内边距：`p-3` 或 `p-4`
- 控件最小点击区：`>= 36px`

## 4. 组件库标准

### 4.1 核心组件清单（必须复用）

- 导航：`IconRail`、`ProjectSwitcher`
- 画布动作：`ActionMenu`、`ControlModes`、`ViewToggles`、`CameraActions`
- 展示模式：`ProposalLayout`、`SubsystemBar`、`SceneBar`、`DeviceInfoCard`
- 面板：`DevicePanel`、`ScenePanel`、`BuildingPanel`、`SettingsPanel`

### 4.2 组件行为约束

- 同类组件同语义同样式，不允许同功能多种交互。
- 禁止在业务页面重复造卡片、按钮、chip 结构。
- 新增交互先落工具函数，再由组件包装。

---

## 5. 交互标准

### 5.1 子系统交互

- 点击行：切换“聚焦子系统”。
- 点击显隐按钮：切换“可见性”。
- 禁止一次点击同时改变聚焦和显隐。

### 5.2 场景交互

- 场景执行要有状态：
  - 空闲：可执行
  - 执行中：显示进行态（spinner + 文案）
  - 完成：显示已激活
- 再次执行新场景默认中断上一场景（后触发优先）。

### 5.3 设备交互

- L2：点击设备立即反馈（开关/亮度/状态）。
- L4：详情面板只展示与当前设备相关参数，不跨设备暴露噪音字段。

---

## 6. 动效标准

- 默认过渡：`duration-200`
- 结构切换：`motion spring`，禁止过度弹跳
- 画布上反馈优先“弱动效 + 强语义”，禁止装饰性粒子泛滥
- 场景执行中允许持续状态动效（如加载旋转）

---

## 7. 可访问性与可用性

- 所有图标按钮必须有 `aria-label`
- 颜色不作为唯一状态表达（要有文案/形态）
- 键盘操作必须可达：`Esc` 取消、`Enter` 确认
- 暗/亮主题对比度保持可读（文本至少 AA）

---

## 8. 工程落地标准

### 8.1 目录规范

- 通用 UI：`packages/editor/src/components/ui/...`
- 展示模式 UI：`packages/editor/src/components/proposal/...`
- 智能工具函数：`packages/smarthome/src/tools/...`

### 8.2 状态分层

- 业务真值：`useScene`（节点、设备运行态、场景数据）
- UI 偏好：`useDeviceState`（子系统显隐、聚焦、覆盖开关）
- 不允许组件私自创建全局真值源

### 8.3 评审清单（PR 必查）

1. 是否复用现有组件/样式 token
2. 是否一次交互只做一件事
3. 是否提供状态反馈（空闲/进行/完成）
4. 是否符合模式权限边界（编辑 vs 展示）
5. 是否有 BDD 场景与验收标准

---

## 9. 本阶段已落地的统一项

- 场景执行支持 `delay/duration` 时间语义
- 展示模式场景栏显示执行中状态
- 子系统交互拆分为“聚焦”与“显隐”两个动作
- 场景面板改为按当前楼层过滤设备与场景
