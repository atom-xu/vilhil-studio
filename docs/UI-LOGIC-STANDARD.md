# VilHil Studio UI 逻辑架构标准（v1.0）

> 目标：统一 UI 背后的状态与行为逻辑，保证“界面一致、状态一致、行为可预测”。  
> 适用范围：所有涉及 `packages/core`、`packages/smarthome`、`packages/editor`、`packages/viewer` 的 UI 逻辑改动。
> 说明：本文件是逻辑细则，视觉规范请参考 `docs/UI-STANDARD.md`。

## 1. 真值源分层（必须遵守）

1. `useScene`（业务真值）
   - 节点数据（`Device`/`Scene`）
   - 设备运行态（开关、亮度、色温等）
   - 场景定义与效果
2. `useDeviceState`（UI 偏好）
   - 子系统显隐
   - 子系统聚焦
   - 仅影响展示，不改变业务真值
3. 组件局部 state（临时状态）
   - 弹窗开关、hover、输入草稿值
   - 不能作为跨组件共享真值

规则：

1. 同一字段只能有一个真值源。
2. UI 不得维护“第二份设备状态真值”。
3. 跨模块共享状态必须先判断是否应上收至 store。

## 2. 工具函数优先原则

任何业务动作必须先实现工具函数，再由 UI 调用：

- 位置：`packages/smarthome/src/tools/`
- 要求：
  1. 可在 React 外调用
  2. 不依赖 DOM
  3. 可被测试脚本直接调用

示例动作：

1. `placeDevice`
2. `removeDevice`
3. `setDeviceParams`
4. `applyScene`
5. `toggleDevice`

## 3. 交互事件流标准

以“展示模式点击场景卡片”为例：

1. UI 触发 `onRun(sceneId)`
2. 调用 `applyScene(sceneId)`
3. `applyScene` 更新设备状态并推送运行状态
4. `SceneBar` 订阅运行状态，显示 `idle/running/active`
5. 渲染层根据最新设备状态刷新视觉效果

要求：

1. 事件流必须单向，不允许组件之间隐式互改状态。
2. 每个关键动作都要有可观测运行状态（至少 idle/running/completed）。

## 4. 楼层与作用域一致性

1. 面板列表默认按当前 `levelId` 过滤。
2. 展示模式只展示当前楼层关联的设备/场景（除非明确切换全局视图）。
3. 禁止“画布是 A 楼层，面板展示 B 楼层数据”。

## 5. 模式权限边界

1. 编辑模式：
   - 可新增/修改/删除节点
   - 可编辑参数与场景
2. 展示模式：
   - 可执行设备与场景
   - 不可修改建筑结构与节点拓扑

`readOnly` 是模式边界的最终约束，UI 仅做显式反馈与引导。

## 6. 性能红线

1. `useFrame` 中禁止触发 React 重渲染。
2. 高频状态变化用 ref 或 store 局部订阅，避免全树更新。
3. 渲染层对象必须考虑 `dispose`，避免几何与材质泄漏。
4. 场景执行过渡采用时间驱动，不做大批量 setState 风暴。

## 7. BDD 验收门禁

每个功能改动必须至少包含 1 个 Given/When/Then 场景：

1. Given 用户处于哪种模式/上下文
2. When 用户执行哪个动作
3. Then UI 与 3D 发生什么可观察变化

没有 BDD 场景的功能，不进入主线验收。

## 8. PR 审查清单（逻辑维度）

1. 是否遵守真值分层。
2. 是否先有工具函数再有 UI 封装。
3. 是否具备可观测状态与清晰事件流。
4. 是否保证楼层作用域一致。
5. 是否满足模式权限边界。
6. 是否触发性能红线风险。
