# VilHil Studio UI 文档入口（先看这个）

> 这份文档给「负责人/业务/设计师」看，不需要代码背景。  
> 目标：5 分钟知道项目当前 UI 到了哪一步、能演示什么、下一步怎么推进。

---

## 1. 一句话总结（当前状态）

VilHil Studio 已经形成可演示闭环：

1. 设计师可以放智能设备（灯、面板、传感器等）
2. 可以创建场景（如回家模式）
3. 客户在展示模式可以点击场景卡片，看到设备状态按时间执行（有执行中反馈）

---

## 2. 你现在可以怎么演示

### 演示路径（建议按这个顺序）

1. 在编辑模式放一盏灯和一个面板
2. 建一个“回家模式”，设置灯光状态变化
3. 切到展示模式
4. 点击“回家模式”场景卡片
5. 观察卡片从“执行中”到“已激活”

### 客户感知点

1. “设备是活的”（可控）
2. “场景是可编排的”（不是死模型）
3. “展示界面和编辑界面是一套语言”（专业度）

---

## 3. 这次我已经落地的改动（非技术版）

1. 场景执行支持“延时 + 过渡时长”
2. 场景卡片有“执行中”状态，不再是点了没反馈
3. 子系统操作拆分为两件事：
   - 选中聚焦
   - 显示/隐藏
4. 场景面板改为“当前楼层视角”，避免全项目信息混乱
5. 输出了统一 UI 设计标准（见下方文档）

## 5. 你可以直接用的验收清单

每次看版本，按下面 7 条检查：

1. 是否 30 秒内能完成一次“设备可控”演示
2. 场景执行是否有清晰状态（空闲/执行中/已激活）
3. 子系统操作是否“一次点击只做一件事”
4. 当前楼层是否只展示当前楼层相关信息
5. 是否保持编辑模式与展示模式视觉一致
6. 是否没有新增“奇怪的新样式”（脱离系统）
7. 是否没有出现“点了没反应”

---

## 6. 下一步计划（你可以直接拍板）

### P0（建议先做）

1. 统一状态真值源（减少不同模块显示不一致风险）
2. 完善场景时间线引擎（并行、暂停、回放）
3. 完成交付页（设备清单/报价）正式版

### P1（随后做）

1. 组件库可视化（Storybook）
2. 设计 Token 自动校验
3. 展示模式埋点（场景点击率、设备交互率）
